# 백업·복원 규칙

## 파일 규격

UTF-8 JSON 파일이며 파일명은 한국 시간 기준 `record-tracker-backup-YYYY-MM-DD_HHMMSS.json`이다. 외부 백업 규격 버전과 내부 데이터 버전은 별도로 관리한다.

```json
{
  "format": "record-tracker-backup",
  "backupVersion": 1,
  "createdAt": "2026-10-07T03:00:00.000Z",
  "data": {
    "version": 3,
    "sessionsByDate": {
      "2026-10-07": [
        { "records": [] },
        {
          "name": "운동",
          "records": [{
            "id": "record-1",
            "timestamp": 1791342000123,
            "result": "success",
            "size": 10,
            "duration": 5,
            "memo": "기록 메모"
          }]
        }
      ]
    }
  }
}
```

- `createdAt`은 유효한 UTC ISO 시각이다. 화면에서는 한국 시간으로 표시한다.
- 새 백업은 `backupVersion: 1`, `data.version: 3`을 출력한다. 복원은 외부 규격 1과 내부 데이터 1·2·3을 지원하며, 내부 버전 1의 기록 목록은 날짜별 첫 세션으로 변환한다.
- 기록의 `result`는 `success`, `fail`, `null` 중 하나다. `size`는 MB 단위 용량, `duration`은 초 단위 길이이며 유한한 0 이상 숫자다. 미입력 값은 내부에서 `null`로 유지하고 localStorage·백업·공유 문자열에 쓸 때 해당 필드만 생략한다. 숫자 `0`과 소수, `result: null`은 그대로 보존하며 메모는 생략 가능한 문자열이다.
- 읽을 때 생략된 용량·길이와 명시적인 `null`은 모두 미입력으로 정규화한다. 기존 `dataMb`·`lengthSeconds` 키도 같은 단위로 읽어 `size`·`duration`으로 변환한다. 새 키와 기존 키가 함께 있으면 둘 다 유효하고 값이 같아야 한다. 서로 다른 값이나 잘못된 숫자는 거부한다.
- 날짜·세션·기록의 배열 순서, 빈 세션, 기록 ID와 원래 타임스탬프를 보존한다. 필터·선택 여부와 무관하게 앱에 반영된 전체 데이터를 내보낸다.
- 현재 선택한 날짜·세션 위치, 테마, 화면 상태, 통계 및 대화상자 초안은 포함하지 않는다. 현재 날짜·세션 위치는 브라우저에 별도로 저장해 새로고침 후 복원한다. `RT1:`·`RT2:` 기록 공유 문자열은 별도의 형식이다.

## 기록 공유와 이전 형식 호환

- 새 공유 문자열은 `RT2:` 뒤에 `{ "version": 2, "records": [...] }` JSON을 gzip·Base64URL로 인코딩한다. 기록 필드와 미입력 생략 규칙은 앱 데이터 버전 3과 같다.
- 기존 `RT1:`과 내부 공유 버전 1은 계속 가져올 수 있다. 접두사와 내부 버전은 일치해야 한다. 공유 버전은 앱 데이터 버전과 별개다.
- 기존 localStorage는 읽는 시점에 덮어쓰지 않고, 다음 저장 시 버전 3으로 기록한다. 기존 백업·공유 문자열도 원본을 변경하지 않고 읽는다.
- 이전 앱은 버전 3 데이터와 `RT2:` 문자열을 읽지 못한다. 새로 저장하거나 내보낸 데이터는 업데이트된 앱에서 사용한다.
- 필드 생략은 기존 `null`과 의미가 같다. 백업 병합에서도 동일한 미입력으로 비교하며 숫자 `0`과 구분한다.

## 세션 이름과 호환성

세션에는 별도 ID가 없으며 날짜별 배열의 위치로 구분한다. 명시적 이름을 먼저 예약한 뒤, 이름 없는 세션에는 현재 위치 + 1부터 겹치지 않는 `세션 N` 이름을 계산한다. 자동 이름은 저장하지 않는다.

현재 위치의 기본 이름과 정확히 같은 기존 `name`도 공통 파서·직렬화 과정에서 생략한다. 위치와 다른 명시적 이름은 보존한다. 기존 데이터의 명시적 이름끼리 중복되어 있으면 전체 교체에서 안내하되, 자동 개명하거나 세션을 합치지 않는다.

## 복원 방식

| 방식 | 데이터 처리 | 적용 후 화면 |
|---|---|---|
| 전체 교체 | 모든 날짜·세션·기록을 백업으로 교체 | 가장 최근 날짜의 첫 세션. 날짜가 없으면 오늘의 빈 세션 |
| 병합 | 현재에만 있는 데이터를 유지하며 새 세션·기록 추가 또는 기존 기록 갱신 | 기존에 보고 있던 날짜·세션 유지 |

두 방식 모두 저장 성공 후 필터를 전체로 바꾸고 기록 선택을 해제한다. 테마 저장 항목에는 접근하지 않는다. 빈 날짜별 세션 배열은 빈 기본 세션 하나로 보정하고 미리보기에 알린다. 날짜가 하나도 없는 데이터도 허용한다.

## 병합 판정

같은 날짜에서 표시 이름이 양쪽에 하나씩 있으면 연결 후보로 제안한다. 이름이 중복되어 모호하면 직접 선택해야 하며, 다른 세션에 연결하거나 새 세션으로 추가할 수도 있다. 현재 세션 하나에 백업 세션 하나만 연결할 수 있다.

연결한 세션 안에서 기록을 다음과 같이 판정한다.

| 조건 | 처리 |
|---|---|
| ID가 같거나 초 단위 시각이 같음 | 같은 기록의 후보 |
| 후보가 하나이고 내용도 같음 | 추가·갱신 없이 건너뜀 |
| 결과·용량·길이·메모·초 단위 시각이 다름 | 현재 기록 유지 또는 백업 기록 적용 선택 |
| ID·시각이 가리키는 대상이 다르거나 후보가 여러 개임 | 연결할 기록을 먼저 선택 |
| ID와 초 단위 시각 모두 다름 | 새 기록으로 추가 |

비교용 시각은 `Math.floor(timestamp / 1000)`으로 계산한다. ID 또는 밀리초 차이만으로 내용 충돌을 만들지 않으며, 생략한 메모와 빈 문자열은 같은 내용으로 취급한다. 백업 값을 선택하면 현재 ID와 배열 위치를 유지하고 백업의 원래 타임스탬프를 포함한 값을 적용한다. 현재 유지·동일 기록 건너뛰기에서는 현재 타임스탬프를 유지한다.

- 날짜나 연결된 세션을 넘어 기록을 중복 제거하지 않는다. 새 세션으로 추가하는 경우 그 세션의 기록을 그대로 보존한다.
- 현재 세션·기록의 상대 순서는 유지하고 새 항목은 백업 내 순서대로 뒤에 추가한다.
- 새 세션의 명시적 이름이 겹치면 이름 변경 또는 기존 세션 연결로 해결해야 한다. 이름 없는 새 세션은 결과 배열에서 자동 이름을 계산한다.
- 미선택 내용 충돌은 일괄 선택할 수 있다. 연결 대상을 바꾸면 기존 충돌 선택을 초기화한다.
- 갱신 결과에 새 시각 겹침이 생기면 적용을 막는다. 기존에 같은 시각을 가진 기록을 임의로 삭제하지 않는다.
- 모든 연결·이름·내용 충돌을 해결해야 저장할 수 있다. 기록·비교 목록은 25개씩 표시하고 상세 내용은 펼칠 때 생성한다.

## 검증과 저장

파일 식별자·버전·생성 시각·달력 날짜·세션 구조·각 기록의 필드를 검사한다. 잘못된 기록을 일부 버리고 복원하지 않으며, 알 수 없는 설정 필드는 앱 데이터로 가져오지 않는다.

미리보기와 충돌 선택은 현재 데이터와 분리된 후보에만 적용한다. 파일 취소·재선택이나 비동기 읽기 완료 순서가 바뀌어도 오래된 후보를 적용하지 않는다. 미리보기 이후 앱 데이터가 바뀌면 다시 계산하고 확인을 요구한다.

최종 적용은 후보 전체 저장 → 기존 예약 저장 취소 → 앱 데이터·화면 교체 순서로 처리한다. 저장에 실패하면 현재 데이터·화면과 예약 저장을 유지한다. 결과가 같으면 저장하지 않는다.

실행 방법과 검증 범위는 [README의 테스트 안내](../README.md#테스트)를 참조한다.
