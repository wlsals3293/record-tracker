# record-tracker

날짜와 세션별로 결과·데이터 용량·길이·메모를 기록하는 브라우저 앱입니다. TypeScript와 Vite로 구성되어 있습니다.

## 주요 기능

- 날짜별 세션 생성, 이름 변경 및 삭제
- 기록의 성공·실패 표시, 용량·길이·시각·메모 편집
- 결과별 필터, 기록 선택 및 통계 확인
- 선택한 기록을 `RT1:` 문자열로 내보내기·가져오기
- 전체 데이터를 JSON 파일로 백업하고 교체 또는 병합 복원
- 밝은 테마·어두운 테마 전환

## 데이터 저장

기록은 현재 브라우저와 사이트 주소의 `localStorage`에 저장됩니다. 서버 저장이나 기기 간 자동 동기화는 제공하지 않습니다. 다른 브라우저·기기에서 사용하려면 백업 파일을 옮겨 복원해야 합니다. 브라우저의 사이트 데이터를 삭제하면 기록도 삭제됩니다.

날짜와 시각은 한국 시간(Asia/Seoul) 기준으로 표시합니다. 현재 세션 위치와 테마 설정은 기록과 별도로 브라우저에 저장하며 백업에는 포함하지 않습니다.

## 개발 실행

Node.js **22.12 이상**과 npm이 필요합니다.

```sh
npm ci
npm run dev
```

개발 서버가 표시하는 주소의 `/record-tracker/` 경로로 접속합니다. 배포용 파일은 `npm run build`로 `dist/`에 생성하고, `npm run preview`로 확인할 수 있습니다.

## 백업과 복원

상단 더보기 메뉴의 **전체 백업 다운로드**는 모든 날짜·세션·기록을 JSON 파일로 내보냅니다. 빈 세션과 메모도 포함하며, 테마·필터·선택 상태·저장하지 않은 대화상자 입력은 포함하지 않습니다. 화면에 이미 반영된 기록 수정은 브라우저 저장이 실패했더라도 백업에 담깁니다.

**백업 파일 복원**에서 파일을 선택하고 다음 중 하나를 고릅니다.

- **전체 교체**: 현재 전체 데이터를 백업 내용으로 바꿉니다.
- **병합**: 현재 데이터를 유지하면서 백업의 세션과 기록을 추가하거나 기존 세션에 합칩니다. 연결 대상과 내용 충돌을 확인한 뒤 적용합니다.

미리보기의 개수와 변경 내용을 확인하고 최종 적용 버튼을 눌러야 저장됩니다. 적용 전 **현재 데이터 백업** 버튼으로 기존 데이터를 내려받을 수 있습니다. 취소·잘못된 파일·저장 실패 시 복원 후보는 적용하지 않습니다.

기존 `RT1:` 기록 공유 문자열은 전체 백업 파일과 다른 형식입니다. 파일 규격, 이름 처리와 병합 판정은 [백업·복원 규칙](docs/backup.md)에 정리되어 있습니다.

## 테스트

```sh
npm test
npm run build
```

`npm test`는 실제 데이터 모듈을 직접 불러와 백업 파싱·병합, 세션 이름, RT1 공유와 저장 모듈을 검증합니다. 저장 모듈 테스트는 `localStorage` API를 테스트 대역으로 교체해 실패 상황도 확인합니다. 대량 기록 사례는 데이터 보존 검증이며 실행 시간의 상한을 보장하는 성능 측정은 아닙니다.

브라우저 테스트는 최초 실행 전에 고정된 Playwright 버전에 맞는 Chromium을 설치합니다.

```sh
npm run test:browser:install
npm run test:browser
```

서버는 `127.0.0.1:4173`에서 자동으로 시작·종료합니다. 실행 전 해당 포트는 비워 두어야 합니다. 각 테스트는 독립된 브라우저 환경에서 실제 다운로드·파일 선택·복원·새로고침·세션 조작을 확인합니다. 실패 시 스크린샷과 실행 추적 파일은 `test-results/`에 남습니다. 이 결과물과 테스트 코드는 배포 파일에 포함되지 않습니다.

GitHub Pages 배포는 일반 테스트, 타입 검사·빌드, Chromium 브라우저 테스트가 모두 통과한 후 진행됩니다.
